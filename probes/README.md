# ArchFlow probes

`probes/` contains building projects, not alternative implementations of
ArchFlow. Each project is a data package loaded by one generic framework
runner. The directory deliberately has no Python package marker and must never
be imported as framework code.

```text
probes/<project_id>/
├─ project.json          immutable project identity and format schema
├─ HEAD                  mutable canonical pointer
├─ input/                authorized external inputs
├─ objects/sha256/       immutable records and artifacts
├─ events/               append-only project history
├─ canonical/            verified accepted C_v snapshots
├─ runs/<run_id>/        branch states, records, candidates, and workspaces
└─ exports/              non-authoritative share packages
```

The generic ArchFlow runner reads the project envelope and invokes only public
framework contracts. P035 defines the side-effect-free project layout and
persistence ports; P036 implements the durable project repository. P020 now
persists the building brief and compilation receipt through that repository;
P018 will add event semantics through the same owner. No probe may bypass it
with its own writer.

## Allowed case content

- the raw request and user-supplied constraints;
- authorized documents, retrieval receipts, and site observations;
- model/tool/run policy selected for this project;
- framework-produced states, alternatives, decisions, receipts, candidates,
  artifacts, and logs.

Inputs and produced outputs must live in separate directories. A derived value
cannot be copied back into `input/` without an explicit user or import receipt.
No persistent project output may be written to a repository-level `.runs/`
directory or hidden by `.gitignore`.
If a new output has no unambiguous destination above, stop before writing it
and ask the project owner to assign one.

## Forbidden case authority

A probe must not contain:

- Python or another executable that derives the building;
- a case-specific Architect implementation;
- fixed room, dimension, material, topology, coordinate, or expert-order
  defaults;
- a geometry/build script authored as the answer;
- a case-specific archive, checkpoint, validator, or state reducer.

Those mechanisms belong in `archflow/` and must operate on more than one
non-isomorphic case. The dependency direction is one-way:

```text
generic runner -> probe data
probe data -X-> framework code
archflow -X-> probes
```

Current probes:

- `test_library/` is the retired narrow boundary smoke retained as historical
  data.
- `test_pantheon/` is a durable project-envelope test generated by
  `archflow.project.bootstrap_raw_request_project`. Its only case-specific
  input is one raw request. It contains no supplied dimensions, functions,
  topology, palette, geometry commands, or expert order, and its receipt
  explicitly denies generation authority and architectural-usability proof.

P020's generic loader now enforces this input envelope. One
`RawProjectRequest@1` may be accompanied by `AuthorizedMaterialInput@1`
records that point to digest-verified immutable objects. Nested files,
executables, direct binary input, and generated schemas in `input/` fail
closed. `DesignBrief@1` and its compilation receipt are framework-produced
run records; they never become authorized input merely because they exist in
the same project.

Later compilers may add further derived records only through the same injected
repository boundary.

## 1. 目标、已定决定与边界

**目标。** 让日常使用顺手。本轮按以下高频路径排序：

1. 在 Hub 对话里让 Agent 改模型：描述修改 → 结果出现 → 查看 → 继续改或接受。
2. 从当前模型出图。
3. 在 MonkeyBoard 上批注、讨论并发设计反馈。

渲染和图纸细调以后会更常用；手动直接建模不是本轮重点。主要在 1440–1920 宽的桌面窗口使用，1280 宽要可用；不专门适配手机宽度。

**已定的用户决定（本方案遵守）：**

- **Q1**（审计 F2）：修改查看中的模型之前，先显式「从此版本继续」；「把第一笔编辑当作一次继续」不采用。
- **Q2**（审计 F1）：工作草稿的保存位置只由用户自己的 Sync 推进；Agent 和提案生成的 Candidate 不推进。重启后仍从用户自己的修改起点开始。
- **Q3**（审计 F10）：未被引用的 Candidate 不再自动删除，保留到用户显式拒绝或归档。
- 本轮以日常使用为目标；主线是本文第 3–7 节，第 8 节的小修与主线并行；需要 runtime 或后端的部分单独标出。

**边界（沿用 #234 的非目标）。** 不重写前端，不先做设计系统，不另存一份项目状态，不把 Stage 简化成普通文件版本，不为界面方便改后端契约。

**成功标准。**

1. Agent 改完模型后，结果自动显示；不打开设计历史，在结果卡片或顶部条上一键「从此版本继续」就能接着改。
2. 任何时刻都能看出：正在看的是哪个模型、它是不是修改起点、有没有接受为 Stage。
3. 从当前模型出图、在 MonkeyBoard 上批注并发反馈，都不需要理解 Candidate ID、分支或内部 run。
4. 常规使用中看不到原始 ID、哈希、API 路径或导出文件名；这些在详情或开发者模式里仍可查。
5. 中文界面没有混入英文文案，英文界面没有混入中文文案；产品名和设计历史用语按命名表保留英文。

## 2. 分类与用语

每个设计点标注一类，并对应审计编号、文档规则或 Issue：

| 标注 | 含义 |
|---|---|
| 【已有但隐藏】 | 能力已存在，界面没有让人看到或够到 |
| 【仅 UI】 | 只改前端即可 |
| 【缺交互】 | 数据与能力齐备，缺一个完整的操作路径 |
| 【缺能力】 | 需要后端或 runtime 新增能力 |
| 【不采用】 | 明确不做，并说明原因 |

用语遵守[产品名称与版本用语](WORK_ENVIRONMENT_AND_EXTENSION_GUIDE.md#产品名称与版本用语)，并针对审计 F7、F13 的用语漂移收敛：

| 中文 | English | 说明 |
|---|---|---|
| 修改起点 | editing base | 下一次修改从这里开始；界面已在用此词（`stage.base.*`） |
| 设计历史 | design history | 历史抽屉的标题 |
| Stage、Branch、Candidate、Exploration | 同左 | 按命名表，不翻译 |
| 接受为 S2 | Accept as S2 | 统一取代「确认下一 Stage」「确认当前模型为 S0」「当前提交」（F7） |
| 从此版本继续 | Continue from this version | 沿用现有文案 |
| 跟随 / 已过期 / 已固定 | Live / Stale / Frozen | 统一图纸、渲染、排版、画板上现有的三套来源状态说法（#254、#272） |
| 其他 Candidate | Other candidates | 不在当前修改线上的 Candidate |

不新增「工作版本」一词：「版本」已有两个含义（F13），并与项目的正式版本冲突。

## 3. 共享的项目上下文

一个 Hub 选中一个项目；每个项目有自己的 Project Runtime，各工作区在同一项目里共享下列上下文（现有机制，不新增项目状态）：

| 上下文 | 谁拥有 | 各工作区如何使用 |
|---|---|---|
| 项目 | Hub 选择 | 所有工作区跟随；切项目时其他项目的工作区保持挂载 |
| 修改起点 + 未同步修改 | MonkeyArch 会话（`useSession`）与工作草稿 | 唯一参照。顶部条、设计历史、对话目标标签、各工作区来源状态都相对它说明 |
| 查看中的模型 | MonkeyArch 视口 | 只影响显示；按 Q1，修改前必须显式继续 |
| 设计上下文 | 工作区回传给 Hub（[ChatShell.tsx:517](../apps/monkeyhub/web/src/ChatShell.tsx#L517)） | 已随每条对话消息发送，只是界面上看不到 → 显示为目标标签【已有但隐藏】 |
| 产出物来源 | 各产出物记录自己的 `modelSource` / Stage | 相对修改起点显示 跟随 / 已过期 / 已固定 |

### 3.1 Agent 结果：自动显示，一键继续（按 Q2）

- Agent 结果完成后自动显示在视口和对话结果卡片上，处于「查看中」状态；修改起点不变【仅 UI】。
- 顶部条与结果卡片都给「从此版本继续」；点一下，修改起点移到该结果【已有但隐藏】（现有继续动作只在底栏和设计历史里）。
- 你在看历史或有未同步修改时，不切走视口，只在结果卡片上提示「Agent 有新结果」【仅 UI】。
- 重启后仍从你自己的修改起点开始（Q2）；未继续的结果留在设计历史的「其他 Candidate」里（Q3）。
- 现状对照：从 Hub 对话打开的结果只作查看（[App.tsx:2019](../apps/monkeyhub/web/workspaces/src/app/App.tsx#L2019)），而 MonkeyArch 自己发起的结果会被自动预览设为基准（审计 F1 补充）。两条入口统一为本节规则。
- 【不采用】Candidate 自动成为修改起点（与 Q2 冲突）；把第一笔编辑当作继续（Q1 已否决）。

## 5. 布局

- **项目栏自动收起**【仅 UI】：打开项目工作区时，左侧项目栏收成图标条（约 48 px），可钉住；1440 宽时工作区从约 620 px 增到约 890 px。2026-09-04 工作台方案的目标是视口不少于 80%（审计 §6）；另提供一个「专注」开关把对话收成窄条，达到该目标。
- **统一顶部条**【仅 UI】：五个项目工作区共用。名称槽按命名表写「产品名 · 中文用途」（MonkeyArch · 建模、MonkeyDiagram · 图纸、MonkeyBoard · 画板；渲染、排版暂用功能名）；上下文槽说明相对修改起点的状态；动作槽放一两个常用动作。它替换建模底栏的「版本 · 查看中」「下一次编辑从……开始」两行（审计 §3），以及渲染、图纸、排版、画板各自的标题栏。

| 工作区 | 上下文示例 | 状态 | 动作 |
|---|---|---|---|
| 建模 | 修改起点 · Agent · 3 分钟前 · S1 之后第 3 次修改「把主入口移到南侧，加雨棚」 | — | 设计历史、接受为 S2 |
| 建模（查看中） | 正在查看 S0 · 9/21 · 不是修改起点（警示样式） | — | 回到修改起点、从此版本继续 |
| 图纸 | 平面 A · 来自 S1 · 修改起点已领先 2 次修改 | 已过期 | 更新到修改起点 |
| 渲染 | 来源：建模当前视图 | 跟随 | AI、实景 |
| 排版 | 汇报 1 · 4 页 · 2 张图已过期 · 1 张已固定 S1 | — | 全部更新、导出 |
| 画板 | 讨论板 · 已保存 · 选中页「平面 A」来自 S1 | 已固定 | 上传、更多 |

- **设计历史抽屉**：从顶部条打开，推开视口（约 260 px），不再覆盖模型；工作区窄于 900 px 时改为覆盖。
  - 顶部固定「修改起点」卡片：摘要、作者、时间、未同步修改数；动作「存为重点版本」「接受为 S(n+1)」。
  - 下面按时间倒序：作者（你 / Agent）、相对时间、摘要、缩略图（有则显示）；悬停出现「查看」「从此版本继续」。「查看」只改视口，修正审计 F11「点 Stage 就改基准」【仅 UI】。
  - 已接受的 Stage 显示为里程碑「S1 已接受 · 日期 · 接受人」【已有但隐藏】。
  - 「其他 Candidate · N」收纳不在当前修改线上的结果，提供「拒绝」「归档」（Q3）【缺能力】：目前没有对应接口（审计 F10）。
  - 「更多」里放 Branch、24 小时恢复点，以及现有的运行与导出卡片。
  - 后台事件到达时刷新设计历史，避免接受时报 `DESIGN_BRANCH_STALE`（审计 F11）【仅 UI】。
  - 「认可方向」（F7）本轮不加：现有认可路由依赖进程内存，重启即失效【缺能力】，另立 Issue。

- **建模工具条单行**【仅 UI】：选择、直线、矩形、推拉、移动 | 撤销、重做 | 更多；平面选择、描图纸、圆弧、自由线进「更多」。Copy 无法触发、Arc / Rotate / Scale / Measure 只能用键盘（审计 W7）属于直接建模，本轮不做。

## 6. 三条路径

### 6.1 Hub 对话 → Agent 改模型

- **过程折叠**【仅 UI】：一轮里的工具调用合并为「过程 · N 步」，默认折叠，展开后用人话；原始请求行（如 `studio_request · GET /api/candidates/…`，[ChatShell.tsx:878](../apps/monkeyhub/web/src/ChatShell.tsx#L878)）只在开发者模式显示。
- **结果卡片**【仅 UI】：缩略图、「模型已更新」、对象数、相对 Stage 的位置、「在建模中查看」「从此版本继续」。关系检查如实显示：零关系时写「没有可检查的关系」，不写「✓ held」（审计 F8）。
- **目标标签**【已有但隐藏】：输入框上方显示这条消息会改哪个模型，如「修改：修改起点 · S1 之后第 3 次修改」。查看其他模型时，标签变为二选一：「改修改起点」或「从此版本继续后再改」（Q1）。
- **新话题**【仅 UI】：「从项目状态继续（不使用旧对话上下文）」改名为「新话题」，放进 + 菜单。
- **「此项目」面板**【仅 UI】：去掉原始的「项目操作」列表（走查中 17 行相同的 `candidate · completed`）、候选 ID 列表和恒为真的「Candidate — not endorsed, not issued」（审计 F7），换成最近 3 个结果和「打开设计历史」；原始列表进开发者模式。
- **Q4 建议：只保留一个对话**【缺交互，待用户决定】。Hub 对话作为唯一的对话输入；MonkeyArch 里默认关闭、关掉后打不开的确定性「对话」栏（审计 F6、W2）不再作为第二个聊天出现，它的提案、候选、结论卡片并入 Hub 结果卡片，确定性意图编译保留为可调用的能力（后端不删）。当前选择和标记作为上下文随消息发送，修正「标记会随句子发送」目前不成立的问题（审计 F6）。

```text
[你] 把主入口移到南侧，加一个 3 m 深的雨棚

Agent：已把主入口移到南立面中段，加了 3 m 深的雨棚；东侧楼梯随入口平移 1.2 m。
  > 过程 · 3 步

  [缩略图] 模型已更新 · 正在查看（修改起点未变）
           93 个对象 · 没有可检查的关系 · 基于 S1 之后第 2 次修改
           [在建模中查看] [从此版本继续]

输入框  标签：修改：修改起点 · S1 之后第 2 次修改
        想在这个项目里做些什么？
        [+ 附件 · 新话题]                  Codex · CLI 默认模型 [发送]
```

### 6.2 模型 → 图纸

- **默认从修改起点出图**【仅 UI】：后端已接受精确的保留模型（[drawings.py:40](../apps/archflow-studio/api/archflow_studio_api/application/drawings.py#L40)），只列 Stage 的限制只在界面里（审计 9.2a）。从 Stage 出图收进「更多」。
- **列表三态**【仅 UI】：每张图显示 跟随 / 已过期 / 已固定；已过期给「更新到修改起点」；重建时保留尺寸并报告断开的锚点（现有能力，审计 9.2a）。
- **图纸命名**【仅 UI】：新建图纸可命名，选择器显示来源（Stage 或修改起点）和时间，不再都叫 `floor-plan.png`（审计 9.4-2）。
- **未保存的修订**【仅 UI】：切换修订前确认；在别的工作区完成的保存要反映到界面（审计 9.2a、9.2d）。
- 「下拉：图纸版本 / 出图模型」两项收进「更多」。

```text
平面 A · 剖切 1.2 m · 1:100      跟随（修改起点）
剖面 1-1 · 1:100                 已过期 · S1   [更新到修改起点]
总图 · 1:500                     已固定 S1
```

### 6.3 MonkeyBoard 批注 → 反馈

- **过期页提示**【仅 UI】：比较页面的 `modelSource` 与修改起点，在页顶提示「此页来自 S1，修改起点已领先 2 次修改」。
- **原位更新页面**【缺能力】：重建的图纸存成新文档，不是旧文档的后继（审计 9.2c），画板只能把它当新页。原位更新需要后继关系，归 #244 / #254。
- **发反馈前的明确选择**【仅 UI】：页面来源不是修改起点时，发送前弹出选择，取代现在静默切换修改起点（[App.tsx:2076](../apps/monkeyhub/web/workspaces/src/app/App.tsx#L2076)）：「先更新这张图」或「从 S1 修改并发送」，并说明修改起点上的修改会留在设计历史里。取消时什么都不切换，标记保留。
- **页卡用 Stage 和时间**显示关联模型，不显示原始来源【仅 UI】。
- 【不采用】把反馈直接施加到修改起点：需要 Agent 把旧图上的标记映射到新模型，属于后端 / Agent 语义，#272 之后再议。

```text
此页来自 S1，修改起点已领先 2 次修改                 [更新此页]

这张图来自 S1
修改起点已领先 2 次修改。发送后会从 S1 开始修改，
修改起点上的修改留在设计历史里，不会丢。
[先更新这张图] [从 S1 修改并发送]
```

## 7. 数据来源与缺口

## 10. 验证

- **每个 PR**：typecheck、build、`archcheck` 与 `archcheck --changed <PR-base>`，以及受影响的单元测试和浏览器场景（chatShell、candidatePreview、documentTracing、drawingCanvas、boardWhiteboard、renderWorkspace、publishWorkspace 等现有套件）；附 1440 / 1280 / 900 宽 × 中文 / 英文 × 深色 / 浅色截图。
- **两道新的常驻检查**：
  - 无原始标识：非开发者模式下，可见文本出现 `hub-cand-`、`studio-cand-`、`@` 后接 12 位十六进制、`GET /api/`、`POST /api/` 等即失败。
  - 语言目录：中文目录里与英文原文相同的值必须在白名单内；白名单取自命名表的产品名、设计历史用语，以及单位和文件格式。
- **A5 的判定**做成纯函数，用表驱动测试覆盖：结果基于修改起点 / 基于其他模型 / 有未同步修改 / 正在看历史 / 重启之后。
- **成功标准 1–3 各一条端到端场景**：
  1. 发送修改请求 → 结果自动显示 → 在结果卡片上一键继续 → 直接发第二条修改。
  2. 查看 S0 → 顶部条显示查看状态 → 回到修改起点；接受 Stage 后顶部条与设计历史一致。
  3. 没有 Stage 的项目：从修改起点出图 → 画板上传该图并批注 → 发送反馈，全程没有原始 ID，也没有隐式切换。

**背景。** 建筑设计并不是从需求直接跳转到形式结果,而是一段由资料、约束、判断和修订共同构成的推导历史。功能决策会影响空间组织,空间组织会产生结构、交通和围护要求;每个后续决定既要继承前期承诺,也会继续约束下游设计。常见的 VAE、GNN、GAN、扩散模型和图像生成方法,主要从已经完成的平面、图关系或图像中学习结果的统计分布,再生成与这些结果相似的新方案(Nauata et al., 2020; Hu et al., 2020)。这些方法适合探索布局、形态和结果多样性,但其学习对象通常是设计的"果",而不是使结果成立的"因"。即使 GNN 能够表示房间或构件之间的拓扑关系,其节点和边也主要描述最终相邻关系,而不一定保存楼梯为什么存在、柱网承担什么作用、层高由哪些条件决定,以及这些决策将继续影响什么。

配备 MCP 工具的通用智能体进一步获得了检索资料、操作软件和生成几何的能力,却仍可能只知道"怎样把模型做出来",而不知道模型中的对象为什么必须存在。工具可以成功生成一组排列整齐的柱子,但不能据此证明柱子连接了基础与上部梁板、避开了楼梯和洞口,或形成了连续传力路径。当前智能体主要依据对话历史、可见几何和最近一次工具回执继续行动;当设计依据散落在过长且非结构化的上下文中时,局部建模成功很容易被误认为整体设计成立,最终产生视觉上合理、实际却无法使用的结果。

**目标。** 本研究提出 ArchFlow,一套位于生成模型与 MCP 工具之上的建筑设计协议。它不以生成另一个终态方案为主要贡献,而是将项目需求、可靠资料、设计依据、既有承诺、几何事实和工具反馈编译成智能体能够读取、执行和验证的设计环境。其基本立场是:建筑设计的核心对象不只是最终模型,而是使模型得以成立的、有约束且可追溯的推导历史。

**方法。** ArchFlow 以全局设计概念为统领,将完整项目历史 \(H_t\) 编译为一组分层嵌套的马尔可夫设计状态。状态层级由全局概念逐步展开到设计阶段、专业系统、构件和具体参数。例如,全局概念可以向下展开为结构体系,结构体系进一步展开为柱网,柱网再包含材料、柱高、跨度和节点细节。越往上,状态越抽象,是对下层信息的有损投影,但仍然足以支持该层级的决策;越往下,信息越具体,而智能体允许修改的范围和权限越窄。

每个状态只保留完整历史中仍会影响该层下一步决策的信息,包括当前事实、已确认参数、有效的设计承诺、尚未完成的设计义务、对象依赖、专业接口、验证证据和已发现冲突。在这一有限且操作性的意义上,状态具有马尔可夫性:智能体可以依据当前状态决定下一步行动,而不必重新解释完整项目历史。被压缩掉的对话、淘汰方案和决策过程不会消失,而是保存在独立的只追加溯源记录中,用于解释、审计和状态重建。

ArchFlow 以树状层级组织状态,同时通过显式接口处理跨分支依赖。每个专业智能体只读取与当前任务有关的状态分支、从上级继承的全局原则,以及其他专业已经编译完成的接口约束。例如,柱网智能体读取建筑轮廓、结构体系、层高、跨度、荷载、无柱区域、允许落柱区域,以及柱子连接上下部结构的义务;它不读取无关的立面风格、家具、景观或其他专家的完整推理文本。如果楼梯影响柱网,交通分支不会把全部上下文交给结构智能体,而是将其转换为禁止落柱区、梁深限制、局部跨度和净高要求。系统隔离的是无关的原始信息,而不是其他分支已经形成的有效约束。由此,每个智能体获得的状态对当前任务而言是充分的,对整个项目而言则是经过选择的局部投影,从而减少过长上下文造成的注意力稀释、错误关联和设计偏移。

设计决策本身不是马尔可夫态,而是作用于当前状态的候选行动。语言模型、规则、优化器或设计师可以提出修改,但不能直接覆盖正式方案。确定性的几何实现层首先将提议转化为可执行计划,MCP 在建模环境中生成候选结果,验证器随后检查实际几何,而不是只检查智能体对结果的文字描述。工具调用成功只表示候选已经执行;只有对应当前任务或未完成义务、处于智能体权限范围内并通过硬性校验的结果,才能形成下一轮正式状态 \(S_{t+1}\)。失败候选及其证据被保留,但不会覆盖上一轮已经确认的设计。

设计依据通过"设计义务"在状态层级中继续传播。例如,使用人数和有效资料可以推导疏散数量、宽度与距离要求,并进一步产生楼梯位置、净高和路径连续性的义务;无柱空间会产生跨度与支撑义务;柱网则产生连接梁板、屋盖和基础的义务。当当前状态缺少作出决定所需的依据时,系统不会允许智能体凭经验直接补全结果,而是暴露缺失信息,调用相关专业智能体或检索工具,从可靠数据来源中补齐依据后再继续推导。

当项目加入新的需求时,依赖关系图只使受到影响的状态、接口和下游义务失效,无关结果继续保留。局部智能体不能擅自修改上级承诺;如果当前条件无法满足,只能提交冲突证据和向上的修订请求。每个新增行动还必须说明它响应了哪项需求、设计问题或未完成义务。无法建立依据关系的几何不能进入正式状态,从而限制与设计目标无关的过度生成和无意义细化。

**初步结果。** 当前原型已在多个独立项目试验中验证状态编译、候选—正式状态分离和局部失效传播。在一次门廊柱数修改中,变化只使相关设计轮次及其下游义务失效,其他结果继续复用。另一次测试中,连接门廊与圆形大厅的屋顶虽然通过了原先声明的检查,却在实际生成后与柱列和屋面构件发生碰撞。系统由此识别出当前状态缺少必要的构件交接条件,将工具反馈编译为新的环境事实和设计义务,并只重新打开受到影响的关系,而没有通过裁切几何、放宽验证器或重新生成整个模型来掩盖问题。

Minecraft 兼容沙箱被用作一种广泛可及、成本较低且可复现的体素验证环境,用于检查支撑、重叠、连通、净空和构件交接。它不被视为现实规范或工程合规证明,而是用于比较同一组智能体和 MCP 工具在终态提示、普通分阶段工作流与 ArchFlow 推导框架下,能否形成更加连续、可验证和可局部修订的设计过程。

**结论。** ArchFlow 将建筑生成从"预测一个可能的结果"重新定义为"推进一段有约束、有依据的设计推导史"。生成模型和 MCP 负责探索并执行候选行动;嵌套的马尔可夫状态负责将每一层未来决策仍然需要的信息从完整历史中压缩出来;设计义务负责把既有决定的影响传递到后续阶段;权限、依赖和验证机制则决定哪些候选能够成为正式设计。不同智能体由此只需读取当前设计树中与其任务有关的分支,同时继承不能遗忘的全局约束和跨专业接口。理想情况下,多个专业智能体可以在该框架内自主推进不同阶段的建筑设计,使缺失依据、设计偏移和无意义膨胀能够被发现、限制并局部修订。

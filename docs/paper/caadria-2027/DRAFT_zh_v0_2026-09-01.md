## 1 引言(1.0 页,含摘要)— 图 1

**第一段:设计是推导史,不是从需求到形式的跳转。** 功能决策影响空间组织,空间组织产生结构、交通和围护要求;每个后续决定既继承前期承诺,也继续约束下游。因此一个设计成立与否,取决于使它成立的资料、约束、判断和修订能否被追溯与查询。

**第二段:现有生成方法学的是"果"。** VAE、GNN、GAN、扩散与图像生成方法从已完成的平面、图关系或图像中学习结果分布,再生成相似方案(Nauata et al., 2020;Hu et al., 2020)。它们适合探索布局与形态多样性,但学习对象是终态。即使 GNN 表示了房间或构件的拓扑,节点和边描述的也是最终相邻关系,而不是楼梯为什么存在、柱网承担什么、层高由什么决定、这些决定还会影响什么。

**第三段:工具智能体知道"怎么做",不知道"为什么"。** 配备 MCP 工具的通用智能体能检索、操作软件、生成几何,却仍可能只会把模型做出来。工具可以生成一排整齐的柱子,却不能据此证明柱子连接了基础与梁板、避开了楼梯与洞口、形成了连续传力路径。智能体依据对话历史、可见几何和最近一次工具回执行动;当依据散落在过长且非结构化的上下文中时,局部建模成功容易被误认为整体设计成立,产生视觉合理、实际不可用的结果。

**第四段:立场与贡献。** 本文提出 ArchFlow,一套位于生成模型与 MCP 工具之上的设计协议。它不以生成另一个终态方案为贡献,而是把需求、可靠资料、依据、既有承诺、几何事实和工具反馈编译成智能体能读取、执行、验证的设计环境。贡献四条:

1. **嵌套的马尔可夫设计状态**:把完整项目历史 \(H_t\) 编译为从全局概念到参数逐层展开的状态,每层只保留仍影响该层下一步决策的信息,被压缩的历史保存在独立的只追加溯源记录中(§3.1–3.2)。
2. **树状分支与显式专业接口**:每个专业智能体只读自己的分支、上级原则和其他专业已编译的接口约束;隔离的是无关原始信息,不是有效约束(§3.3)。
3. **设计义务与候选/正式分离**:决策是作用于状态的候选行动;只有响应了某项需求或义务、在权限内、且实际几何通过硬校验的候选才成为正式状态;义务把既有决定的影响传递到后续阶段(§3.4–3.5,§4)。
4. **局部失效与可验证修订**:新需求只使受影响的状态、接口与义务失效;在 27 个配对修复回合中,依赖范围修复与整链重建的验证通过率相同,而平均重算比例为 0.173,影响集精确率与召回率为 1.0(§6.2)。

**第五段:边界与组织。** 本文的经验证据来自三个非同构沙箱案例与两个古典建筑的复原推导;沙箱不是规范合规证明,而是可复现的验证环境。摘要承诺的三种机制对比(终态提示、普通分阶段、ArchFlow)见 §5.2 **[待做]**。文章组织如下:§2 综述四条相关线索并给出区分表;§3 给出概念模型;§4 描述系统;§5 实验设计;§6 结果;§7 讨论与边界;§8 结论。

**图 1**:终态生成 vs 推导史生成——左侧是"提示→几何";右侧是"状态→候选行动→实现→验证→正式状态",旁路是只追加溯源记录。

## 3 概念模型(1.2 页)— 图 2

**3.1 三个对象,三种权限。** 项目版本的正典状态 \(C_v\)(单写者,正式方案)、分支工作状态 \(D_{v,k}\)(面向下一步决策的操作性马尔可夫状态)、整段历史 \(H_{\le t}\)(只追加证据)。状态对行动充分,历史对论证必要。加载历史或重建状态不证明外部模型或工具可被重放。

**3.2 嵌套状态与逐层投影。** 状态从全局概念展开到设计阶段、专业系统、构件和参数。越向上越抽象,是对下层的有损投影但足以支持该层决策;越向下越具体,智能体允许修改的范围和权限越窄。每层保留:当前事实、已确认参数、有效承诺、未完成义务、对象依赖、专业接口、验证证据、已发现冲突。

实现层面的诚实说明 **[裁决]**:V4 中层级不是五个独立状态机,而由**类型与权限**实现——阶段由成熟度相位与相位门实现(研究→功能→场地→方案→扩初→候选协调→可执行);不可逆象限的声明在过门时编译为硬承诺;专业由六类发展义务(结构支撑、交通、围护开口、材料、建造、使用)实现;构件由构件成熟度与语义构件树实现;参数由几何程序参数与接口基准实现。§3 应给一张"层级 ↔ 实现对象"的对照表。

**3.3 树、分支与专业接口。** 每个专业智能体只读:与任务有关的状态分支、上级继承的全局原则、其他专业已编译的接口约束。柱网智能体读建筑轮廓、结构体系、层高、跨度、荷载、无柱区、允许落柱区,以及"柱连接上下部结构"的义务;不读立面风格、家具、景观或他人的完整推理文本。楼梯影响柱网时,交通分支不把全部上下文交给结构智能体,而是转换为禁止落柱区、梁深限制、局部跨度与净高要求。

接口在坐标层面的实现:构件的端点由其依赖面的**接口基准**共同派生,而不是各自复述数值;构件模板携带对接、支承、净空等**接口义务**,由基准解析(P090/P091)。这是"派生而非复述"原则下沉到几何的形态,也是 §6.3 碰撞事件的修法。

**3.4 义务作为数据类型。** 义务带稳定身份、来源、作用域、消费者、验证器、证据要求与状态(开放/受阻/已解决)。人数与资料推导疏散数量、宽度与距离,再产生楼梯位置、净高、路径连续性的义务;无柱空间产生跨度与支撑义务;柱网产生连接梁板、屋盖与基础的义务。缺依据时系统不允许凭经验补全,而是暴露缺失,调用专业智能体或检索,从可靠来源补齐后再推导。

**3.5 决策是候选行动。** 语言模型、规则、优化器或设计师提出修改,不能直接覆盖正式方案。确定性实现层把提议转成可执行计划,MCP 在建模环境中生成候选,验证器检查实际几何。工具成功只表示候选已执行;只有对应当前任务或未完成义务、在权限内、通过硬校验的结果才形成 \(S_{t+1}\)。失败候选及其证据保留,不覆盖上一轮。

**图 2**:一次精确基底转换——提议、确定性门、提交/拒绝、工作状态、正典状态、证据历史。

## 4 系统(1.4 页)— 图 3

**4.1 编译一次设计移动。** 自然语言移动 → 绑定到精确 \(D_{v,k}\) 的决策算子 → 状态增量 → 前置条件与锁检查 → 直接效应 → 类型化依赖/失效闭包 → 就绪编译 → \(D_{v,k+1}\)。闭包只沿显式的 `invalidates` 与 `requires_revalidation` 边到有界不动点;编译器不猜测未命名的依赖,也不规定修复答案。状态摘要含分支纪元,用于精确基底拒绝。

**4.2 实现层、MCP 与验证器。** 语义构件 → 实现规格 → 族(参数化 / 资产 / 混合)→ 几何程序 → 实现回执,绑定构件、几何对象与平台对象。沙箱观察器读回体素,检查支撑、重叠、连通、净空与构件交接;CAD 端由读回的 3DM 检查对象数、宿主与碰撞。截图只是只读证据;执行回执不带验收权限。

**4.3 依据暴露与检索。** 决策依据索引把查询、快照、采纳记录分片索引到决策;证据充分性编译器区分"事实在场"与"研究充分",输出继续/扩域/人审/完成四种前沿状态;澄清请求把缺失依据交回人或专业席位。

**4.4 冲突上交。** 局部智能体不能改上级承诺;当条件无法满足,只能提交冲突证据与向上的修订请求。实例:万神殿复原 run-010 的正面台阶数冲突记录以 `OPEN_HUMAN_REVIEW` 状态保留,未被自动裁决 **[核]**。

**4.5 依赖失效与修复执行器。** 同一被接受的增量下的三种策略:仅改目标(无闭包)、整链重建、依赖范围修复(只重算类型化闭包)。"保留"的操作定义是记录摘要逐字相同。

**4.6 每个行动必须有依据。** 语义绑定必须引用承诺与证据;模板参数逐值带依据引用;进入几何创作前必须对目录逐族作答(选用某模板或给出弃用理由)。无法建立依据关系的几何不能进入正式状态。

## 5 实验设计(1.2 页)— 图 4、图 5

**5.1 案例与环境。** 三个非同构沙箱案例(诊所、车间、合院),每个是独立项目,自带需求、证据、构件树、几何与推导痕迹;框架只拥有通用的实验与度量契约。两个古典建筑复原(万神殿、圆厅别墅)作为机制案例:前者在体素沙箱与 CAD 两端,后者在 CAD 端。Minecraft 兼容沙箱是广泛可及、低成本、可复现的体素验证环境,不是规范合规证明。

**5.2 实验 A:三种机制对比 [待做]。** 摘要承诺:同一组智能体与 MCP 工具在(i)终态提示、(ii)普通分阶段工作流、(iii)ArchFlow 推导框架下,能否形成更连续、可验证、可局部修订的设计过程。需要定义:

- 基线 (i):一次性提示直接生成整栋建筑几何,允许工具调用,无状态编译与验证门。
- 基线 (ii):按阶段分次提示,前一阶段输出作为下一阶段上下文,无义务、无依赖闭包、无硬校验。
- 指标:完成率与硬验证通过率(可验证);跨阶段承诺被后续阶段违反的次数(连续);一次局部修改后被改动的记录数与被保留的承诺比例(可局部修订);token 与调用成本。
- 控制:同一 provider 配置、同一案例、同一预算;每格一次尝试,失败与超时保留。

**5.3 实验 B:上下文与验证消融(P062)。** 3 案例 × 3 条件(完整链 / 生成上下文消融:仅去除 `DesignProgram.relationships` / 验证消融:复用完整链候选、省略一个命名评估器)。同一 provider 画像;预注册;计划、运行、失败、完成各态精确重载;一次尝试规则。

## 7 讨论与边界(0.8 页)

- **机制迁移而非普适性能**:三案例 + 两复原证明机制可跨非同构建筑迁移,不证明建筑设计整体上被解决。
- **单席而非多智能体**:当前 provider 是单一提案席;摘要结论段的"多个专业智能体自主推进"是框架的目标态。专业隔离目前由义务类型、分支上下文与接口约束实现,专业级并行推进未实现。
- **层级由类型实现**:嵌套状态不是五层状态机(§3.2)。
- **声明依赖的不完整**是诚实残差;义务与验证器是兜底网;从验证失败回流为新声明边是后续工作。
- **验证器依赖**:验证器契约公开,金标集独立;报告闭包的假阳性/假阴性。
- **沙箱与 CAD 边界**:体素沙箱是受控实验基底;B-rep 实现只作机制证据,不进指标。
- **"限制过度生成"**是机制主张,尚未测量 **[裁决:是否在实验 A 里加一个"无依据几何被拒绝的比例"指标]**。
- 审稿刀口(义务只是改名的约束?依赖闭包只是溯源?基线弱?验证器自证?三栋楼证明什么?沙箱不是 CAD?失败被删了?)各对应 §2/§5/§7 的一句。

## 8 结论(0.3 页)

ArchFlow 把建筑生成从"预测一个可能的结果"重新定义为"推进一段有约束、有依据的设计推导史"。生成模型和 MCP 探索并执行候选行动;嵌套状态把每层未来决策仍需要的信息从完整历史中压缩出来;义务把既有决定的影响传到后续阶段;权限、依赖和验证决定哪些候选成为正式设计。在 27 个配对修复回合中,依赖范围修复以 0.173 的重算比例达到与整链重建相同的验证通过率 **[+ 实验 A 一句,待做]**。缺失依据、设计偏移和无意义膨胀由此能被发现、限制并局部修订。

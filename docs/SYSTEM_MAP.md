# ArchFlow system map

## adapters

### adapters.cad_execution — `archflow/adapters/cad_execution.py`
Prepare, supervise and independently verify one fail-closed Rhino .3dm export of an exact compiled program.
- owns: RhinoCadProgramBinding and RhinoCadExportIdentity: the P036 record/branch/stage identity an export is bound to; the immutable export plan: workspace layout, script, completion token, host witness and the full validation denominator digest; the STA PowerShell/COM worker source and its shell-free encoded command; supervising the blocking worker, collecting its output, and independently cleaning the Rhino host it started; readback verification: the saved file's physical objects, semantics, bounds, counts, layer colours and document user text against the denominator; the execution receipt and its status
- does not own: translating the program into a script - adapters.cad_program; selecting what a patch rebuilds - adapters.cad_patch; reading the .3dm - adapters.three_dm_inspector; writing anything into the project repository - it has no project-repository or canonical-write authority; runtime.project_runner retains the receipt; choosing the workspace - the caller supplies an existing speculative workspace
- api: `prepare_rhino_three_dm_export`, `execute_rhino_three_dm_export`, `verify_rhino_export_readback`, `build_rhino_com_powershell_source`, `build_rhino_com_powershell_command`, `discover_rhino_executables`, `RhinoCadProgramBinding`, `RhinoPatchBase`, `CadExecutionStatus`, `CadExecutionError`
- invariants: a successful process exit is never sufficient - the saved file is read back independently and must match the denominator; the export identity refuses any up_axis but Z-up and any unit outside millimeter/meter/inch/foot; every path is constrained to the caller-supplied workspace; no shell interpolation and no launcher file exists; the plan is immutable once prepared and identified by its plan digest; discovery is read-only: it never launches or attaches to Rhino

### adapters.cad_patch — `archflow/adapters/cad_patch.py`
Diff two compiled programs into the closed set of operations a Rhino rebuild must redo, and the prelude that carries the rest of the prior document forward.
- owns: per-object structural digests of what the CAD script actually emits; the diff into changed / added / retired / kept object ids, with a reason per object; closing the rebuild set over input edges (consumers of a rebuilt object, producers of a rebuilt operation's inputs); the Rhino-side prelude that opens the prior model, deletes the retired objects and re-stamps the kept ones; refusing a patch that cannot be expressed, so the caller rebuilds instead
- does not own: emitting the rebuilt operations - adapters.cad_program's operation_subset does; running or verifying the patched export - adapters.cad_execution; deciding whether to patch at all - runtime.project_runner's _export chooses reuse, patch or rebuild; comparing two runs' saved geometry - studio.validation's compare
- api: `select_patch_operations`, `build_patch_prelude`, `PatchSelection`, `CadPatchError`
- invariants: an object is rebuilt only when its structural digest or its analytic bounds actually changed, beyond tolerance; the rebuild set is closed over input edges - nothing consumed or produced by a rebuilt operation is left stale; an inexpressible patch fails CadPatchError, which is a signal to rebuild, never a partial document

### adapters.cad_program — `archflow/adapters/cad_program.py`
Translate a compiled neutral geometry program into one deterministic, semantics-carrying rhinoscriptsyntax build script, plus the analytic denominator it must reproduce.
- owns: the supported operation vocabulary and its rhinoscriptsyntax emission (solid, revolve, extrusion, loft, boolean union/difference/intersection, linear and radial array, transform, curve); the layer path and layer colour tables derived from components and material assignment; the archflow:* object user text each physical object must carry (expected_object_semantics); the analytic per-object bounds the realization must reproduce (expected_object_bounds); applying a datum-bound base_level to profile points (lift_to_base_level); the P103 partial emission of an operation subset
- does not own: running the script, saving the file or verifying the readback - adapters.cad_execution; deciding which operations a patch rebuilds - adapters.cad_patch; reading the resulting .3dm - adapters.three_dm_inspector; compiling the program - compilers.geometry; any design decision: it holds no design authority and adds no geometry
- api: `translate_to_rhino_python`, `expected_object_semantics`, `expected_object_bounds`, `lift_to_base_level`, `CadTranslation`, `CadTranslationError`
- invariants: an unsupported operation kind fails CadTranslationError rather than being dropped silently; the same program translates to the same script bytes - the emission is deterministic and self-contained; coordinates pass through as the program states them; the translator performs no frame conversion; every physical object is named and carries its archflow:* identity strings

### adapters.model_provider — `archflow/adapters/model_provider.py`
Invoke one explicitly configured JSON model command as a detached, bounded subprocess and return a typed invocation receipt.
- owns: ModelProviderSpec: the command, protocol, timeouts, byte and token caps, isolation flag, and the spec fingerprint; the async subprocess invocation with its input/output byte limits and timeout; decoding the command's answer (including codex exec JSONL) into ArchFlowModelOutput@1; the Codex CLI configuration and its detached, tool-free prompt; turning a failure into a typed receipt status rather than an exception
- does not own: the request/receipt contracts themselves - ports.model; authority, envelopes and provider lifecycle - production.provider_runtime and production.responsibility; what the model is asked to author - capabilities.geometry_proposal; any project write, workspace handle or world mutation, and any fallback provider
- api: `AsyncJsonCommandModelProvider`, `ModelProviderSpec`, `ModelCommandProtocol`, `create_codex_cli_model_provider`
- invariants: no shell and no fallback: exactly one explicitly configured command is executed; input and output are hard-capped in bytes; exceeding a cap is a typed failure receipt; the adapter holds no authority token - it is bound behind one by production.provider_runtime

### adapters.three_dm_inspector — `archflow/adapters/three_dm_inspector.py`
Read one .3dm file headlessly and return a deterministic, JSON-compatible summary of what is actually saved in it.
- owns: the ThreeDmInspection shape and its versioned key sets (the one place the schema's required keys are declared); reading layers, objects, instance definitions and references, counts by type and by layer; document and object user strings; world bounds: aggregate, per named object, and the visible-bounds witnesses that back each leaf bound; native material and render-material tables and each object's material binding; per-object encoded-geometry digests and morphology analysis (planarity, curve sampling); the typed, fail-closed inspection error codes
- does not own: producing the file - adapters.cad_execution; deciding whether the file matches a program - adapters.cad_execution's readback verification; importing RhinoCommon, starting Rhino, or choosing where anything is persisted; comparing two inspections - studio.validation's compare
- api: `inspect_three_dm`, `ThreeDmInspection`, `ThreeDmInspectionError`, `ThreeDmInspectionErrorCode`, `REQUIRED_INSPECTION_KEYS`, `SUPPORTED_INSPECTION_SCHEMAS`
- invariants: read-only: rhino3dm is imported lazily, one immutable byte snapshot is read, and no Rhino process is started; bounds come from saved visible geometry, never from Brep control points; an object geometry digest hashes encoded geometry only - object attributes cannot change it; an unreadable or unsupported file fails with a named error code, not a partial summary

## capabilities

### capabilities.declaration — `archflow/capabilities/declaration.py`
Define and gate the mandatory typed decisions a stage requires, and compile the gate-passed ones into hard commitments.
- owns: DeclarationQuadrant and DeclarationKind: the vocabulary a stage's decision fields are grouped and typed by; DeclarationField and StageDeclarationContract, with each field's unit, authorized range and range provenance; the deterministic geometry cross-checks that bind a declared value to the accepted massing; the fail-closed stage gate over a declaration set (validate_stage_declarations); compiling gate-passed declarations of named quadrants into HARD Commitments; selecting exactly the decision basis shards a contract's fields need
- does not own: storing declared field values - the framework holds contracts, the provider supplies values; the commitment lifecycle and validation - archflow.state.commitments and archflow.validation; which seat may declare in which quadrant - capabilities.discipline_seats; stage opening or closure - archflow.state.stage_workflow and control.stage_closure
- api: `DeclarationQuadrant`, `DeclarationKind`, `DeclarationField`, `DeclarationError`, `GeometryCheck`, `StageDeclarationContract`, `validate_stage_declarations`, `compile_declaration_commitments`, `select_decision_basis`
- invariants: the gate fails closed: a missing, out-of-range or geometry-contradicted field blocks the stage; a declared value is checked against the massing by a deterministic measure, within the contract's tolerance ratio; only gate-passed declarations become commitments, and only in the quadrants named

### capabilities.discipline_seats — `archflow/capabilities/discipline_seats.py`
Divide authoring across role-scoped seats: what a seat may write, what it may read, what it hands the next seat, and in which round it runs.
- owns: SeatSpec: the component subtrees a seat writes, its disciplines, phases, quadrants, the seats it consumes and whether it reviews; the owned subtree and ancestor computation over the component tree; compiling a deterministic SeatHandover from a committed seat: its datums, exclusion bounds, digests and object constraints; projecting the design state onto one seat as SeatAuthoringContext, so sibling subtrees never leak; refusing a seat that publishes a datum over a project level or grid axis; checking declared engagements against a handover's exclusion bounds; scheduling seats into parallel rounds by handover dependency
- does not own: producing any geometry inside a seat's scope - capabilities.element_producers; running the rounds, exporting or writing seat records - runtime.project_runner; the declaration contract and its gate - capabilities.declaration; who is authorized to write canonically - archflow.contracts.authority (seats carry no_authority); reading the project's authored seat pack from disk - studio.candidate's seats adapter and tools/run_project.py
- api: `SeatSpec`, `SeatError`, `SeatHandover`, `HandoverKind`, `DeclaredEngagement`, `owned_subtree`, `ancestors`, `compile_handover`, `project_seat_context`, `check_seat_datums`, `check_handover_exclusions`, `schedule_seats`
- invariants: a seat's authoring context contains only its subtree, its ancestors and the handovers it consumes - a sibling subtree is never visible; a handover is bound to the base state digest it was compiled from and carries its own digest; a seat may not publish a datum id that a project level or grid axis already owns; entering another seat's exclusion bound is a violation unless a DeclaredEngagement is on record; seats carry explicit no_authority for canonical write, design and stage acceptance

### capabilities.element_producers — `archflow/capabilities/element_producers.py`
Turn a State Record's Element@1 rows into geometry operations, datum bindings, published datums and materialized relations, reading references rather than computing coordinates.
- owns: the producer dispatch table PRODUCERS: column-array, capitals, beam, pediment, wall, prism, ring, loft, dome-cap, declined; reading Element@1 entities off a StateRecord into ElementRow, in production order; topological production order: an element that names another (or its published `<id>-top`) is produced after it; publishing `<id>-top` interface datums an element grants to what it supports; declaring the support relations that construction materializes (ProducedRelation), with engagement or rise; typed declination: a component owned, looked at, and left without geometry for a stated reason; the building-local frame id and the +Y extrusion convention every producer emits
- does not own: turning a reference into a plan coordinate or an elevation datum - capabilities.reference_resolver; the wall solid, its through-cuts and its hosted voids - capabilities.wall_solver; window and door member geometry inside a void - capabilities.opening_solver; resolving a symbolic datum binding into a number - compilers.geometry; measuring whether a declared relation actually holds - capabilities.relation_checks; which rows a seat may produce, and the seat's exclusions - runtime.project_runner and capabilities.discipline_seats
- api: `ElementProducerError`, `ElementRow`, `ProductionContext`, `element_rows_of`, `produce_rows`
- invariants: no producer computes a plan coordinate itself; every position goes through resolve_plan; elevations leave as (datum id, offset) bindings, never as literal numbers; an element referencing another is produced after it; a reference cycle or a missing element fails ElementProducerError; an unknown producer name fails typed rather than being skipped; an overlap into a support exists only as a declared ENGAGEMENT parameter, recorded on the relation

### capabilities.geometry_proposal — `archflow/capabilities/geometry_proposal.py`
Author, compile and retain bounded rounds of a provider's neutral geometry proposal against one exact state, with no fallback and no acceptance authority.
- owns: the strict provider request and response contracts (the authoring output topology and its function contracts); the bounded round loop, its policy knobs (round cap, bookkeeping completion, progress budget, partial acceptance, stall escalation) and its resume seam; decoding a provider's full or edit-shaped answer into a typed GeometryProgramProposal without inventing geometry; semantic coverage validation of a proposal against the state, commitments, seat scope and required component bindings; the lineage / round / proposal / deferral / escalation records and their persistence through the repository; reloading one exact compiled program from its retained record
- does not own: compiling the proposal into objects and digests - compilers.geometry; invoking the model provider or signing its receipt - ports.model and production.provider_runtime; accepting a stage or writing canonical state - it holds no hard-gate or canonical-write authority; producing geometry from records itself - capabilities.element_producers (the runner feeds it an authored proposal); any CAD translation or execution - archflow.adapters
- api: `produce_geometry_program_proposal`, `resume_geometry_program_proposal`, `load_geometry_proposal_lineage`, `load_compiled_geometry_program`, `proposal_authoring_output`, `proposal_edit_authoring_output`, `GeometryProposalPolicy`, `GeometryProposalProviderIdentity`, `GeometryProposalStatus`, `GeometryProposalProductionError`
- invariants: no fallback: a round that does not compile is rejected with issues, never patched into acceptance; the provider receipt's identity must match the declared GeometryProposalProviderIdentity; the proposal is bound to one exact design-state digest and predecessor program digest; a round is capped by policy; exhausting the cap deposits a deferral or escalation record, not a result; every round is retained before the next one is authored

### capabilities.opening_solver — `archflow/capabilities/opening_solver.py`
Fill a wall's hosted voids with window and door types, emitting frame, glazing and leaf members as one hosted assembly per opening.
- owns: WindowType and DoorType: the proportions of one opening family (frame width/depth/projection, glazing or leaf thickness, offsets, leaf count and clearances); solving a void into frame members, a pane, or jambs/head plus one or two leaves; the arrayed form: one member definition placed void.count times along the wall; assembling the members into a HostedAssembly with its roles and interface reference
- does not own: where the opening is, how big it is, or which storey it belongs to - capabilities.wall_solver's HostedVoid says; cutting the host - capabilities.wall_solver owns the tool and the boolean; choosing which type an opening gets - capabilities.element_producers maps opening id to type; any project coordinate or level elevation
- api: `WindowType`, `DoorType`, `OpeningSolution`, `OpeningSolverError`, `solve_window`, `solve_door`, `solve_openings`
- invariants: a type carries proportions only - no position, no level, no absolute size; every member is placed relative to the void the wall granted; a void whose opening id has no type fails OpeningSolverError rather than being left empty

### capabilities.reference_resolver — `archflow/capabilities/reference_resolver.py`
Resolve the record's symbolic plan and elevation references against grids, levels and host lines - the one resolver every producer calls.
- owns: the reference vocabulary: GridRef, GridIntersection, AxisPoint, HostAlong, LevelRef, OffsetFrom; parsing a reference from its JSON form; resolving a plan reference to one (x, z) coordinate; resolving an elevation reference to a symbolic (level datum id, offset) pair; ReferenceContext: the grids, levels and host lines a resolver may read; HostLine: a host element's reference line and points along/across it
- does not own: emitting any geometry operation from a resolved point - capabilities.element_producers; publishing a datum an element grants - capabilities.element_producers; substituting a datum id for its numeric elevation - compilers.geometry; the ProjectLevels / ProjectGrids record shapes themselves - archflow.state.geometry_program; derivation expressions - archflow.state.derivation
- api: `ReferenceError`, `ReferenceContext`, `HostLine`, `GridRef`, `GridIntersection`, `AxisPoint`, `HostAlong`, `LevelRef`, `OffsetFrom`, `parse_reference`, `resolve_plan`, `resolve_elevation`
- invariants: resolve_elevation never returns a number - the compiler is the only thing that turns a datum id into one; an unknown axis, level or host fails ReferenceError rather than defaulting; a resolver reads only grids, levels and host lines; it cannot see components or geometry

### capabilities.relation_checks — `archflow/capabilities/relation_checks.py`
Measure a State Record's relations against realized geometry and record held / violated / unchecked as a RelationCheckReport@1.
- owns: the checker table keyed by a relation's validator check_kind (today only support_contact); the support-contact measurement: subject top against object bottom plus declared engagement or rise, and against a named datum; the element-standing-on-a-level orientation of the same check; reporting a relation with no validator or no checker as `unchecked` rather than as passing; the report's three-state counts, held / fully_checked flags and its digest
- does not own: which relations reach the check - runtime.project_runner filters the record to kind `support` before calling; producing the geometry or the analytic bounds it measures - capabilities.element_producers and compilers.geometry; declaring the relation in the first place - archflow.state.state_record; turning a violation into a stage or run verdict - runtime.project_runner; any repair or healing of geometry that fails a check - nothing on the spine does this
- api: `check_relations`, `RelationCheckReport`, `RelationCheck`, `RelationCheckError`
- invariants: nothing is healed: a check only measures and reports; `held` alone is not a green light - an unchecked relation does not count against it, so held must be shown with fully_checked; a relation whose objects have no realized bounds fails RelationCheckError instead of being scored; the report carries the record digest it was measured against

### capabilities.wall_solver — `archflow/capabilities/wall_solver.py`
Solve one wall from its location line, thickness, height and storey datum into a solid, a cut tool per opening, and the hosted voids openings are filled into.
- owns: WallElement geometry: reference line, normal, plan points and plan rectangles in wall coordinates; OpeningRequest: where an opening sits along the wall, its width, sill, head and repeat count/step; enumerating the wall solid, one tool per opening and the single boolean difference that cuts them; granting each opening a HostedVoid - its aperture in wall coordinates plus the object ids it may use; rejecting overlapping openings, openings past the wall ends, and openings that hit a declared exclusion
- does not own: what fills a void - capabilities.opening_solver decides frames, panes and leaves; where the wall is in the project - capabilities.reference_resolver resolves its two plan references; the storey elevation as a number - the wall carries a base level datum id, resolved by compilers.geometry; reading opening requests off the record - capabilities.element_producers
- api: `WallElement`, `OpeningKind`, `OpeningRequest`, `HostedVoid`, `WallSolution`, `WallSolverError`, `solve_wall`
- invariants: the wall is one solid; every opening is a void request the wall hosts, never a separate subtraction chain; an opening's position is expressed in wall coordinates (along, across), never in project coordinates; a contract violation - non-positive size, an opening outside the wall, overlapping voids - fails WallSolverError

## compilers

### compilers.geometry — `archflow/compilers/geometry.py`
The one pure compiler: bind a neutral geometry proposal to an exact state, order its operations, digest its objects, or return an explicit rejection receipt.
- owns: the operation dependency graph, its deterministic order and per-object digests; frame, component and semantic-binding digests that bind a program to one state; resolving DatumBinding references into literal parameters (the only place a datum id becomes a number); asset resolution and the substitution receipt when a requested asset is replaced; assembly role validation and revision preconditions against a prior program; the typed issue vocabulary and the compile receipt whose status is ACCEPTED or a rejection
- does not own: authoring or repairing a proposal - capabilities.geometry_proposal; producing operations from records - capabilities.element_producers; any CAD script, execution or readback - archflow.adapters; persisting the program - the caller writes it through archflow.project.repository; accepting a stage - it holds no acceptance authority
- api: `compile_geometry_program`, `resolve_interface_datums`, `CompiledGeometryProgram`, `CompiledGeometryObject`, `GeometryCompilationResult`, `GeometryCompilationReceipt`, `GeometryCompilationError`, `GeometryCompileStatus`, `GeometryIssue`, `GeometryIssueCode`, `AssetSubstitutionReceipt`
- invariants: pure: it reads inputs and returns a result, and never writes or mutates anything; a structurally invalid input raises; a semantically rejected proposal returns a receipt with issues and no program; every issue is appended, not short-circuited, so one round reports every independent failure; the compiled program is bound to the state digest and, on a revision, to the predecessor program digest; operation order is deterministic for one proposal

## contracts

### contracts.authority — `archflow/contracts/authority.py`
The single source of the all-False authority-flag block that every retained record carries.
- owns: the default authority field names (DEFAULT_AUTHORITY_FIELDS); constructing a key-sorted, all-False authority block (no_authority); rejecting a malformed, duplicated or non-'_authority' field name (AuthorityContractError)
- does not own: deciding which record needs which flags (each writer passes its field list); enforcing that a producer really holds no authority (a static scan in the test suite holds the inline-block count at a baseline); record serialization (each record type)
- api: `no_authority`, `DEFAULT_AUTHORITY_FIELDS`
- invariants: every returned flag is exactly False; field names are lowercase identifiers ending in _authority; output keys are sorted, so canonical serialization is independent of caller order

### contracts.canonical — `archflow/contracts/canonical.py`
Deterministic finite-JSON encoding and the sha-256 primitives every record digest on the spine is built from.
- owns: canonical JSON text with sorted keys, no NaN/Infinity and no cycles (canonical_json); its UTF-8 bytes and lowercase sha-256 (canonical_json_bytes, canonical_digest); the 64-hex digest validator (require_sha256); typed rejection of values that cannot be canonical JSON (CanonicalValueError)
- does not own: excluding a record's own digest field before digesting (project.digests); record file bytes on disk, which add a trailing newline (project.repository); which fields a given record digests (each record type decides)
- api: `canonical_json`, `canonical_digest`, `require_sha256`, `canonical_json_bytes`, `CanonicalValueError`
- invariants: a pure function of the value: no filesystem, no clock, no randomness; ascii=True and ascii=False digest differently, so a record keeps the form it was written in; a non-finite float, a non-string mapping key or a cycle raises rather than being coerced

### contracts.fields — `archflow/contracts/fields.py`
Strict scalar and deterministic-tuple validators shared by the newer typed contracts.
- owns: bounded, trimmed, non-empty text (text); enum-instance and finite-number checks (enum_value, finite_number); exact mapping key-set checks used to detect schema drift (exact_mapping); payload field primitives: mapping, list_of, tuple_of, typed_tuple, string_tuple, unique, number, positive, refs, ids; scheme-qualified logical-ref syntax, rejecting file: and drive-letter paths (logical_ref); sorted-unique bounded tuples of refs and identifiers (deterministic_refs, deterministic_identifiers)
- does not own: identifier syntax itself, which it delegates to project.refs.require_identifier; the logical-ref validator used by the operational-state family (state.operational_state.require_logical_ref is a parallel); digesting or serializing the values it validates (contracts.canonical)
- api: `deterministic_identifiers`, `deterministic_refs`, `enum_value`, `exact_mapping`, `finite_number`, `identifier`, `ids`, `list_of`, `logical_ref`, `mapping`, `number`, `positive`, `refs`, `string_tuple`, `text`, `tuple_of`, `typed_tuple`, `unique`
- invariants: a tuple field must already be sorted and unique; the validator never sorts on the caller's behalf; collections are bounded at 4096 items; validation is total: an unexpected type raises rather than being coerced

## ports

## production

### production.provider_runtime — `archflow/production/provider_runtime.py`
Activate any model provider behind the P053 responsibility contract, so a live provider is reachable only through a signed envelope and a lifecycle receipt.
- owns: the model responsibility contract definition (request and receipt schema refs); binding an AsyncModelProvider into a handler that keeps the production authority token in a trusted closure; AuthorizedAsyncModelProvider: the only surface a caller sees after envelope validation; activation from an explicit identity, from a ModelProviderSpec, or as the Codex Agent CLI; the bounded in-process collector of already-validated invocation envelopes
- does not own: the control plane, tokens, signing and lifecycle state machine - production.responsibility; executing the command - adapters.model_provider; the request and receipt contracts - ports.model; the replay provider the runner uses instead of a live one - runtime.project_runner's RecordedProposalProvider
- api: `activate_model_provider`, `activate_provider_from_spec`, `activate_codex_agent_cli_provider`, `bind_async_model_provider`, `model_responsibility_contract`, `AuthorizedAsyncModelProvider`, `InvocationEvidenceCollector`
- invariants: the model adapter never sees the authority token - it stays in the binding closure; every returned receipt came out of an envelope the router validated; activation always produces a lifecycle receipt and a handover decision; there is no unqualified live provider

### production.responsibility — `archflow/production/responsibility.py`
The P053 responsibility control plane: who may act for a responsibility, under what authority epoch, and with what signed, verifiable envelope.
- owns: ResponsibilityContract, ProviderIdentity, ProviderRegistration and their digests; the lifecycle state machine (provider modes, qualification, handover decision and receipt, authority epoch); ProductionAuthorityToken and its grant nonce and signature; InvocationEnvelope: a provider receipt plus the authority that produced it, signed and validated; the split capability surface: ResponsibilityRouter (register, resolve, invoke, validate) versus ResponsibilityReconciler (qualify, activate); portability enforcement: safe ids, schema refs, and refusal of machine-local paths in payloads; shadow invocation of a non-active provider
- does not own: any model-specific contract or execution - ports.model and adapters.model_provider; the model responsibility definition and its convenience activations - production.provider_runtime; what a receipt payload means - the capability that authored the request; persistence: it is in-process state, retained by whoever holds the envelope
- api: `create_responsibility_control_plane`, `ResponsibilityRouter`, `ResponsibilityContract`, `ProviderIdentity`, `ProviderMode`, `ProductionAuthorityToken`, `InvocationEnvelope`, `HandoverDecision`, `ResolutionStatus`, `InvalidProviderReceipt`, `InvalidInvocationEnvelope`, `NoProductionAuthority`, `StaleAuthority`, `StaleHandover`, `ContractConflict`, `UnknownProvider`, `ProviderUnavailable`, `ProviderLifecycleError`, `ProviderInvocationFailed`
- invariants: lifecycle mutation is a separate object capability from invocation - a router holder cannot activate a provider; a handover is refused unless the caller's expected binding digest matches the current state (compare-and-swap on authority); an envelope is signed over the authority token and the receipt digest, and validated before any receipt is trusted; a payload carrying a machine-local path or an unsafe id is refused; an invocation by a provider that is not the active one is refused unless it is an explicit shadow call

## project

### project.digests — `archflow/project/digests.py`
The one semantic digest of canonical project-state content, taken with the state's own declared digest field removed.
- owns: digesting canonical state content excluding state_sha256 (project_state_sha256); verifying a declared state_sha256 against the recomputed digest
- does not own: canonical JSON encoding and the raw sha-256 primitive (contracts.canonical); the byte digest of a written record file, which includes a trailing newline (project.repository)
- api: `project_state_sha256`
- invariants: a declared state_sha256 that disagrees with the content raises; the digest is over content without its own digest field, so it is stable under re-declaration; never writes the filesystem

### project.inputs — `archflow/project/inputs.py`
The one reader of a project's work-in-progress inputs: the designer's authored State Record and seat pack, at the two paths the layout owns (ADR-007).
- owns: reading the work-in-progress inputs at the layout's authored_record and seat_pack paths; the typed refusals for those two files - absent, unreadable, undecodable, not JSON, not a State Record - each carrying the path it wanted (InputsError and its four kinds); how each file is identified on the way out: the record's own content digest, and the sha-256 of the seat pack's bytes
- does not own: naming the two paths (project.layout); parsing SeatPack@1 (tools.run_project, the Studio's adapters/seats.py); retaining anything; nothing read here is indexed, digested or verified by the repository (project.repository); deciding which run uses the record (runtime.project_runner, studio.candidate); the meaning of the record it parsed (state.record)
- api: `AuthoredRecord`, `SeatPackFile`, `load_authored_record`, `load_seat_pack_file`, `InputsError`, `AuthoredRecordMissing`, `AuthoredRecordInvalid`, `SeatPackMissing`, `SeatPackInvalid`
- invariants: never writes: the work-in-progress container is read, and nothing about it is retained until a run uses it; absent and unreadable are different refusals, and each names the file it wanted; the record's content digest is taken from the record, never recomputed here (ADR-003); both files are decoded as strict UTF-8; another encoding is invalid, not absent; the seat pack comes back as the mapping the project authored; no seat is parsed, defaulted or invented

### project.layout — `archflow/project/layout.py`
Pure mapping from a project root and identifiers to filesystem paths, with no directory creation and no writes.

## validation

### validation.engine — `archflow/validation/engine.py`
The read-only hard gates that turn a canonical state plus a candidate submission into a validation receipt.
- owns: the validator protocol (Validator); the artifact-presence and artifact-evidence gate (ArtifactPresentValidator); the production claim gate compiled only from authorized hard commitments (AuthorizedCommitmentClaimsValidator); the obligation-discharge gate (ObligationDischargeValidator); deterministic receipt id derivation from state, submission and findings; fail-closed aggregation: base mismatch and validator exceptions become ERROR findings (validate_submission)
- does not own: the receipt shape (validation.model); the submission (submission.model); promotion after a pass (project.repository.prepare_transition); domain checks such as relations, cad readback or usability (capabilities/relation_checks.py and the archived lanes)
- api: `validate_submission`, `ArtifactPresentValidator`, `AuthorizedCommitmentClaimsValidator`, `ObligationDischargeValidator`, `RequiredClaimsValidator`
- invariants: read-only: the gates never mutate state and never write anything; a base mismatch between the submission and the checked state is itself an ERROR finding; an exception inside a validator fails closed as a validator.exception finding; RequiredClaimsValidator is compatibility-only and refuses to gate production state

### validation.model — `archflow/validation/model.py`
The spine's validation result vocabulary: a finding, and the receipt that binds a verdict to the exact submission content checked.
- owns: finding severity (Severity); the finding value: code, message, severity, evidence refs (Finding); the receipt binding a verdict to a submission digest and a checked state (ValidationReceipt); the pass/fail consistency rule
- does not own: running validators (validation.engine); the deterministic-check envelope used by relation and stage checks (validation.contracts, the parallel being folded away); the submission it reports on (submission.model)
- api: `Finding`, `ValidationReceipt`, `Severity`
- invariants: passed is true exactly when no ERROR finding exists; submission_digest must be 64-hex: a receipt cannot float free of the content it checked; never writes the filesystem

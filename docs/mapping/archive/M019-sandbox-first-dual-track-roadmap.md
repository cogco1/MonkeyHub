# M019 — Sandbox-first dual-track roadmap

- Origin: Modify
- Status: Done
- Depends on: P024

## Goal

Realign the generated development map around a platform-neutral geometry and
sandbox acceptance path while retaining Minecraft as a parallel downstream
adapter rather than the proof authority for ArchFlow.

## Write scope

- `governance/work_registry.json`
- `docs/DYNAMIC_MAP.md`
- `docs/mapping/`

## Acceptance

- The core Gold path ends in a reloadable accepted sandbox building, not a
  Minecraft world.
- Neutral geometry separates Architect-supplied architectural semantics from
  a generic deterministic geometry kernel.
- Parametric operations, assembly specifications, and provenance-bound detail
  assets can coexist without teaching the geometry kernel building types.
- Door and window assemblies preserve host cuts, frames, leaves, glazing,
  interfaces, and clearance envelopes as typed bindings.
- Voxel realization is a derived validation view, not the only canonical
  geometry representation.
- Minecraft observation, mutation recovery, `.schem`, and other platform
  exporters remain visible as a parallel downstream lane.
- Existing completed evidence is not relabeled as proof of the missing neutral
  geometry or sandbox Gold capabilities.

## Tests

- Generated-map determinism and registry validation.
- Architecture firewall.
- Planning-card and dependency-link rendering.

## Stop conditions

- Stop before claiming the geometry kernel, sandbox realization, or Gold run is
  implemented.
- Stop if the roadmap makes a platform exporter authoritative over accepted
  geometry.
- Stop if detail assets or assemblies can bypass provenance and hard
  validation.

# P081 — Branch research to stage-convergence integration

- Origin: Planning (P079/P080 integration)
- Status: Done
- Depends on: P079, P080

## Goal

Put P079 and P080 on the real branch-to-design acceptance path. A P078 branch may
compile design context only from a complete evidence-sufficiency receipt for its
exact scope, and a stage may advance only with a valid exact-base convergence
receipt. Prove the same contract on a historical reconstruction and a synthetic
modern learning pavilion, then expose the receipts as progress-panel data.

## Acceptance

- `BranchRAGProgress.COMPLETE` cannot authorize design context without an exact
  P079 receipt; successor-universe expansion produces the next P078 scope.
- Stage advancement requires an exact P080 receipt and rejects stale, regressive,
  or hidden-expansion transitions.
- A synthetic modern fixture proves grid-to-facade, courtyard-to-access, and
  floor-height-to-stair/service dependencies without framework-owned vocabulary.
- Candidate selection applies hard feasibility as a non-compensable filter before
  soft preference scoring; style or personal preference can never offset a failed
  code, safety, dimension, or adopted-standard gate.
- Text facts, visual regions, drawings/designer sketches, measurements, and
  derivations enter the same typed frontier. Visual and sketch observations remain
  candidates with explicit epistemic roles; they never become dimensions or
  authoritative decisions merely because a model labelled them.
- The Pantheon runner consumes both receipts before its later stages archive.
- Promoted P060/P061/P062 integration evidence reloads through relocation
  anchors after project data moves to the runtime workspace; tests do not
  assume a repo-local project root.
- Workspace project discovery is a reusable read-only `archflow.project`
  capability with typed location results and anchor-integrity checks; tools
  and tests configure roots but do not own discovery logic.
- Token and operation telemetry separates one-shot direct execution from initial
  compilation and later local revisions; no token-saving claim is made without a
  comparable receipt pair.

## Stop conditions

- Stop if integration weakens P078 branch isolation or P036 persistence authority.
- Stop if a progress status can be inferred from record presence alone.

## Tests

Branch research closure, exact-base stage advancement, hard-filter/soft-ranking,
multimodal candidate routing, modern fixture, Pantheon runner gate integration,
telemetry comparison, workspace-relocation reloads, full discovery, and
architecture firewall.

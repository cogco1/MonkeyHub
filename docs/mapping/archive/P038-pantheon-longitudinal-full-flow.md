# P038 — Pantheon longitudinal full-flow acceptance

- Origin: Planning
- Status: Done
- Depends on: P026, P031, P033, P051

## Goal

Use the same `probes/test_pantheon/` project as a longitudinal acceptance run.
Starting from the user's short request for an ancient Roman Pantheon, ArchFlow
must retrieve evidence, compile commitments and a program, derive alternatives,
coordinate state-responsive experts, generate and repair candidates, and
finally realize and validate an accepted platform-neutral sandbox artifact.

P037 is only the project-envelope bootstrap. P038 is the point at which the
Pantheon test may be called a complete architectural workflow.

## Write scope

- `probes/test_pantheon/`
- `tests/integration/test_pantheon_full_flow.py`
- `docs/mapping/`

## Acceptance

- The only authored case input is the user's short raw request and later
  explicit approvals or revisions.
- CLI retrieval supplies Pantheon evidence with provenance; no framework file
  contains Pantheon facts, proportions, dimensions, column counts, materials,
  topology, or geometry commands.
- Functions, capacities, areas, relationships, site response, resources,
  topology, massing, dimensions, and palette are derived per project and
  retained with exact-base receipts.
- The run advances through brief, programming, site/resource coordination,
  schematic design, design development, candidate coordination, and execution
  readiness without skipping or confusing maturity levels.
- Within each maturity phase, the Primary Architect chooses tools and
  state-responsive experts from the current operational state and obligations
  rather than following a universal fixed expert schedule.
- Alternative branches, trade-offs, a rejected or revised candidate, readonly
  aesthetics, hard usability gates, and explicit selection authority remain
  distinct and reloadable.
- Geometry-program evaluation and sandbox realization bind the exact same
  accepted candidate. No external-platform success is usability proof.
- The accepted run, neutral package, operational trace, evidence, expert
  advice, validation, evaluation, approval, and mutation receipts reload after
  restart. Canonical HEAD remains unchanged without separate promotion
  authority.

## Tests

- Raw-input-only and framework-instance-literal scans.
- Retrieval-to-brief-to-program provenance chain.
- Multi-branch design and state-responsive expert trace.
- Rejected/repaired and accepted candidate history.
- Explicit neutral geometry, sandbox realization, paper views, and use
  validation.
- Full project close/reopen.

## Stop conditions

- Stop before using a framework default as a Pantheon answer.
- Stop before any optional live execution without platform-specific
  authorization.
- Stop if an intermediate result bypasses the project repository.
- Stop before calling the test complete unless the final accepted artifact
  passes hard usability gates.

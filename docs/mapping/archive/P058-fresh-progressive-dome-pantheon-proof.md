- Origin: Planning
- Status: Ready

## Goal

Produce fresh, rerunnable evidence that the formal runtime can generate a
building through semantic-and-geometry co-birth and progressive deepening:
first a meaningful coarse dome, then shell and oculus, then local coffering,
followed by a new Pantheon-scale run through the same generic path.

## Acceptance

- The three dome stages share stable component identity and carry matching
  semantic, coarse/detailed geometry, lifecycle, dependency, and validation
  evidence at each stage.
- The Pantheon run begins from raw project input and invokes the formal runtime;
  it cannot pass by loading P026/P038 final state or frozen geometry as output.
- The probe contains project data and framework-produced evidence only, with no
  case-specific Python generator, validator, or fallback.
- The accepted sandbox artifact is traceable to exact P036 run records and the
  active P053 provider epochs used to produce it.
- Claims distinguish deterministic scripted-provider proof from any separately
  enabled live Agent CLI smoke and report skipped live execution honestly.

## Tests

- Three-stage dome longitudinal integration test.
- Fresh raw-input-to-accepted-sandbox Pantheon integration test.
- Frozen-output and case-code firewall, provenance reload, architecture
  firewall, and full unit discovery.

## Stop conditions

- Stop if the proof imports a Gold answer, specialized Pantheon constructor, or
  historical final geometry into the active generation path.
- Stop before claiming Minecraft, Rhino, Revit, structural, drainage, or
  fabrication equivalence.
